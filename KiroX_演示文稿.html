背景与痛点 · PAIN POINTS

为什么传统自动化难以胜任 Kiro 自动化注册？

AI 辅助编程浪潮下，传统浏览器 UI 自动化在现代云厂商风控体系面前暴露出的致命瓶颈

🛑 资源沉重与并发崩溃
  • 内存黑洞：单个 Chromium 无头实例即占用 300MB~800MB 内存，多并发任务极易导致操作系统 CPU/内存雪崩。
  • 启动延迟大：需加载并渲染完整 DOM 树与静态资源，单个注册周期拖长至 2~5 分钟。
  • 维护脆弱：前端界面元素或 Class 规则微调，脚本选择器即大面积失效，维护成本极其高昂。
🎯 特征裸露与风控狙击
  • 环境特征显著：navigator.webdriver、CDP 调试端口、自动化扩展特征被 AWS 风控引擎精准识别。
  • 缺少网络指纹：标准 HTTP 客户端缺失现代浏览器 TLS 握手套件顺序与 HTTP/2 参数，JA3 瞬时暴露。
  • 频繁遭遇 OTP 400：使用机房 IP 或指纹异常时，AWS 验证码接口直接抛出 OTP 400 阻断。
🧩 鉴权冗长与邮箱碎片化
  • 长链路协同：跨越 OIDC 设备码、邮箱双向验证、JWE 密文加密、SSO 及多阶段 Token 置换。
  • 邮箱协议碎片：Outlook IMAP/Graph、第三方商业临时邮箱、自建私有邮件系统缺乏统一抽象。
  • 容灾与重试缺失：传统脚本遇到网络抖动往往直接崩溃，导致「密码已设但令牌未取」，白白报废邮箱。
核心价值 · VALUE PROPOSITION

KiroX 破局之道：纯协议级原生架构

彻底舍弃繁重无头渲染，通过深层协议逆向与工业级工程设计实现质的飞跃

⚡ 纯协议级极速执行与低开销

全流程直接基于原生 HTTP/TLS 请求完成，无需下载任何渲染资源。毫秒级网络 I/O 响应，注册周期压缩至数十秒内；单机可流畅并发数十个 Worker 线程，内存占用仅需数十 MB。

🛡️ 真实 TLS / JA3 / 环境深度伪装

基于定制 tls-client 引擎，高度仿真真实 Chrome 的密码套件、扩展列表、椭圆曲线与 HTTP/2 首部流；内置高仿真 performance.timing 与屏幕参数模型，从容穿透风控检测。

📬 全渠道高可用邮箱矩阵集成

开箱即用集成 Outlook 邮箱池 (IMAP / Graph 双引擎)、iCloud 消息列表、MoeMail 临时邮件服务、自建 Cloud-Mail 系统及 MailNest 商业邮箱，提供高度解耦的统一收件与验证码提取规范。

🔄 闭环健壮状态机与实时探活

密码设置成功即时原子标记，网络异常自动原地触发 3 次幂等重试，杜绝邮箱无谓损耗；注册成功自动调用 Verify 探测账号存活 (alive) 与 CodeWhisperer 信用额度 (creditLimit/Used)。

暴露高内聚 Go 方法至前端 window.go.main.App | 异步轮询与事件推送机制，毫秒级同步任务执行进度、存活状态及敏感后端 URL 自动脱敏。

task：并发 Worker Pool 控制、串行等待调度、Context 优雅中断 | core：15 步注册流水线编排与容错 | email & browser：多协议邮箱提取抽象 + 指纹构建与缓存。

业务流转 · PROTOCOL PIPELINE

15 步纯协议注册流水线全景拆解

精准复刻 AWS Builder ID 认证注册与 Kiro 令牌置换的完整状态机流转

阶段一：初始化与会话握手
  • 01 OIDC 注册：请求注册端点，换取动态 Client ID 与密钥。
  • 02 设备注册：申请 Device Code 及专属用户验证 URI。
  • 03 邮箱分配：从配置邮箱源智能调度可用邮箱实体。
  • 04 门户交互：预热加载远程 AppJS 配置并初始化指纹。
  • 05 流程初始化：初始化 AWS 注册工作流会话上下文。
阶段二：验证码与安全加密
  • 06 提交邮箱：提交账号并根据状态分流至 Signup 分支。
  • 07~08 Profile：用户身份配置初始化并启动注册环境。
  • 09~10 验证码：请求 SendOTP，多协议轮询并提取验证码。
  • 11 创建身份：提交有效验证码确认建立云端身份标识。
  • 12 设置密码：JWE 密文安全提交密码 (置位 passwordSet)。
阶段三：凭证交换与存活探活
  • 12.8 SSO 准备：启动 SSO 工作流验证，打通登录会话。
  • 13 SSO Token：获取 SSO Access/Refresh Token (3次重试)。
  • 14 Kiro 授权：发起 Kiro 客户端授权，置换临时 Auth Code。
  • 15 交换令牌：置换最终 Kiro Refresh Token 与 ClientSecret。
  • 校验 存活状态：探测账号存活 (alive) 与 CodeWhisperer 额度。
反爬攻防 · STEALTH ENGINEERING

多维指纹模拟：从传输层到应用层的立体防御

以工业级仿真标准对抗云厂商风控，保障高并发下的高通过率

🌐 传输层：TLS / JA3 / HTTP2 指纹仿真
  • 真实 Chrome TLS 握手：基于定制 bogdanfinn/tls-client，精准模拟真实 Chrome 浏览器的 Client Hello 特征。
  • 密码套件与扩展对齐：完整还原 Cipher Suites、Supported Versions 与 Elliptic Curves 顺序，杜绝特征异常。
  • HTTP/2 协议层规整：对齐 SETTINGS 帧参数与伪首部 (:method, :authority, :path) 顺序，消除 WAF 识别漏洞。
🎭 应用层：全维度浏览器上下文构建
  • 时延模型高斯分布：GenPerfTiming 算法动态模拟 DNS 查询、TCP 连接、DOM 解析等真实耗时，击穿静态脚本检测。
  • 屏幕特征离散化：自动生成符合市场规律的分辨率、色彩深度（如 1920-1080-1040-24）与显示区域。
  • Client Hints 动态对齐：精准匹配 Sec-CH-UA、User-Agent 与操作系统平台，消除环境矛盾硬伤。
📊 监控层：D3 指纹偏移与缓存持久化
  • D3.js 指纹偏移可视化：前端直观呈现各批次任务的指纹熵值与偏移波动，辅助运营者实时评估指纹健康度。
  • 磁盘级指纹缓存预热：通过 identity_cache 模块管理本地指纹缓存，保障单账号注册期间环境绝对一致。
  • 动态 AppJS 配置预热：并发执行期间提前异步 WarmAppJSConfig，大幅减少注册前置握手时延。

网络治理 · PROXY & ROUTING

住宅代理池调度与网络纯净度治理

解决 OTP 400 与网络风控的核心基石：多协议支持、出口体检与任务级隔离

🔌 全协议支持与批量管理
  • 协议全覆盖：全面支持 SOCKS5、HTTP、HTTPS 代理协议，保障各种复杂内网穿透需求。
  • 认证格式规范：支持 protocol://user:pass@host:port 格式，支持单条录入与文本批量秒级解析。
  • 一键启停管控：直观的代理状态切换开关，随时隔离异常节点，保障活跃代理池的高可用性。
🌍 实时出口检测与网络体检
  • 真实出口探测：自动请求全球出口检测端点，解析出公网真实 IP 与所在国家/地区/城市坐标。
  • 运营商与 ASN 识别：明确区分住宅宽带 (Residential) 与机房数据中心 (Datacenter)，指导网络选型。
  • 毫秒级延迟测速：直观展示 TCP 握手与 HTTP 往返延迟 (Ping/Latency)，智能标记最优链路。
🛡️ 任务隔离与风控排查体系
  • 任务级代理绑定：创建批处理任务时支持指定代理通道或直连，不同批次任务环境严格物理隔离。
  • OTP 400 智能诊断：针对常见的 OTP 400 拦截，精准提示更换高纯净度住宅代理，消除盲目试错。
  • 生态合作保障：特别鸣谢 IPWO 提供覆盖 195+ 国家与地区的优质住宅代理生态。
调度与容错 · RESILIENCE

高并发任务编排与资产零损耗容错体系

在对抗网络波动与平台风控的同时，实现任务调度的高吞吐与业务资产的极致安全

⚡ 弹性并发控制与削峰延时

支持自由配置注册总数量、并发 Worker 数量以及串行批次间等待延时。既可榨干网络吞吐极限，又可通过节奏拟人化延时有效削峰，降低被上游风控识别为机器刷量的概率。

🛑 全链路 Context 级优雅中断

注册核心各步骤全面监听 Go context.Context。用户在界面点击「停止」时，系统毫秒级安全中断所有正在进行的网络请求，立刻回收协程与连接池资源，不留僵尸进程。

🔐 密码设置原子化与免浪费重试

密码一旦在 AWS 端设置成功，立刻打上 passwordSet: true 原子标记。后置步骤（SSO 或 Token 交换）若遭遇抖动，仅执行原地 3 次退避重试，绝不将邮箱重新置回初始态报废。

📂 数据域物理隔离与日志敏感脱敏

应用运行时严格分离业务数据 (data/)、浏览器指纹缓存 (cache/) 与注册成果 (accounts.json)；运行日志全链路正则过滤敏感 API 终结点与 Token 凭证，兼具易调试性与安全性。
